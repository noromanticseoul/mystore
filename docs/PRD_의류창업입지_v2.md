## 1. 배경과 문제

- 의류 매장 입지는 **유동인구 체감, 중개인 정보, SNS 분위기**로 결정되는 경우가 많다. 근거를 수치로 설명하기 어렵다.
- 서울시 상권분석서비스는 상권 × 업종 × 분기 매출·유동·점포를 공개하지만 **결과 지표**다. 방문 전 관심도, 실제 대중교통 승하차, 현재 시점 경쟁 점포는 비어 있다.
- 이전 단계(v5)에서 12개 요인 그룹으로 의류 상승 예측 모델을 만들었고, 13개 분기 백테스트에서 **v5 블렌드(규칙 순위 + 모델 순위 평균)**가 가장 안정적이었다(AUC 0.661, Top 10 적중 8.23).
- 이번 단계에서 외부 데이터 7종을 추가 수집했고, 요인 그룹별 최적 비중을 학습했다.

**핵심 질문**
> 다음 분기 이 상권의 의류 매출이 작년 같은 분기보다 오를까? 어떤 요인 때문인가?

**부가 질문**
> 주변 카페 상권의 흐름이 의류 매출을 앞서 보여 주는가?

## 2. 목표와 비목표

### 목표
0. (v2) 실무자가 **검증된 숫자로 보고**하고, **자기 조건(지역·규모)으로 좁혀** 볼 수 있게 한다.
1. 공공 데이터 + 외부 데이터를 **(분기, 상권코드)** 하나의 키로 결합한 학습 데이터를 만든다.
2. 요인 그룹별로 **어느 비중일 때 과거 13개 분기에서 가장 잘 맞았는지** 학습해 제시한다.
3. 모델을 모르는 실무자가 **요인 비중을 직접 움직여 보고**, 그 조합이 과거에 몇 개를 맞혔는지 즉시 확인하며 2026년 3분기 후보 상권을 고를 수 있게 한다.
4. 기본 추천은 **검증 게이트를 통과한 방식(v5 블렌드)**으로 고정해, 사용자 조정과 검증된 기준을 구분한다.

### 비목표
- 임대료, 카드사 결제 데이터 등 유료·신청형 데이터
- 개별 점포 단위 매출 예측 (상권 단위까지만)
- 네이버 데이터랩·검색(키 발급 불가), 인스타그램(공개 API 없음) 데이터
- 실시간 갱신 (분기 단위 배치 갱신)

## 5. 기능 요구사항

### FR-01 외부 데이터 수집 파이프라인
- 소스별 수집 스크립트(`collect_*.py`), 키는 로컬 파일에서만 읽고 저장소·공유본에 포함하지 않는다.
- 요청 제한(429)에 대비해 재시도·대기·이어받기를 지원한다.
- **수용 기준**: 소스별 행 수·기간·커버리지가 `coverage_summary.csv`로 저장된다.

### FR-02 항목 사전
- 모든 피처에 출처, 요인 그룹, 업종(의류/카페/공통), 갱신 주기, 커버리지, 누수 여부를 기록한다 (`feature_dictionary.csv`).

### FR-03 요인 그룹 정의 (16개)

| 그룹 | 화면 이름 | 출처 |
|---|---|---|
| demand | 수요 규모 | 공공 |
| trend | 수요 추세 | 공공 |
| fit | 고객 적합 | 공공 |
| pattern | 주말·시간대 | 공공 |
| access | 유동·접근성 | 공공 |
| spend | 구매력 | 공공 |
| compete | 경쟁 강도 (낮을수록 좋음) | 공공 |
| stable | 상권 안정성 | 공공 |
| facility | 집객시설 | 공공 |
| resident | 배후 거주 | 공공 |
| cafe | 동반 업종(카페) | 공공 |
| companion | 동반 쇼핑 업종 | 공공 |
| ext_search | 검색 관심도 | 외부 |
| ext_subway | 지하철 유동 | 외부 |
| ext_bus | 버스 유동 | 외부 |
| ext_cafe | 카페 상권 지표 | 외부 |

- 각 그룹 점수는 같은 분기 상권 간 **백분위(0~1)**로 표준화한다.

### FR-04 요인 비중 학습
- 그룹 점수의 가중합으로 순위를 만들고, 가중치(합 100%)를 **각 평가 분기 이전 자료로만** 학습한다(롤링).
- 비교 대상: 추세 유지 규칙(B2), v5, v5 블렌드, v5+외부, W1(그룹 가중합), W2(그룹 + 모델 확률).
- 그룹 빼기·더하기(ablation)로 각 그룹의 기여를 확인한다.
- **결과(2026-11-19)**

| 방식 | AUC | Top 10 적중 | v5 블렌드 대비 |
|---|---|---|---|
| v5 블렌드 (현재 공개) | **0.661** | **8.23** | 기준 |
| v5 + 외부 블렌드 | 0.663 | 8.15 | 차이 유의하지 않음 |
| W2 (그룹 + 모델) | 0.654 | 8.00 | 유의하지 않음 |
| W1 (그룹 가중합) | 0.620 | 7.46 | AUC 유의하게 낮음 |

- 학습된 비중(W1): 수요 추세 88%, 상권 안정성 8%, 수요 규모 2%, 지하철 유동 1%.
- 빼기 실험: 수요 추세 제거 시 AUC 0.643 → 0.574, Top 10 8.0 → 6.3 (유의). 고객 적합 제거 시 Top 10 7.2 (유의).
- 확장 모델 SHAP 기여: 수요 추세 24%, 업종 검색 추세 14%, 수요 규모 7%, 날씨 7%, 주말·시간대 7%, 지하철 유동 6%.

### FR-05 의류 × 카페 관계 검증
- 같은 상권 카페 매출·점포 변화가 0/1/2분기 뒤 의류 상승을 맞히는지 AUC로 확인.
- **결과**: 모든 시차에서 AUC 0.49~0.51. 예측력 없음. 화면 성적표에 "카페 흐름으로 의류를 예측하는 효과는 확인되지 않음"을 명시하고, 상세에는 현재 카페 점포 수만 참고로 표시한다. (v2)

### FR-06 검증 게이트 (v1.2 유지)
1. Top 10 평균이 현재 공개 방식 이상, 승이 패보다 많음
2. 분기별 Top 10 표준편차가 현재 이하
3. 보정 후 ECE ≤ 0.05
- 이번 단계 후보는 모두 1번에서 탈락. **기본 순위는 v5 블렌드 유지.**

### FR-07 실무자 서비스 화면 (v2 개정)

| 성적표 | 기준 방식 13개 분기 성적(평균·최저), 등급별 과거 실제 상승 비율, 보정 오차, 외부 데이터 효과(유의하지 않음), 카페 관계(예측력 확인되지 않음) |

#### 7-2. 요인 묶음 (v2)
| 묶음 | 포함 그룹 | 실무자용 설명 |
|---|---|---|
| 성장 흐름 | 수요 추세, 수요 규모 | 최근 매출이 늘고 있고 시장이 큰가 |
| 고객·소비 | 고객 적합, 구매력, 주말·시간대, 배후 거주 | 의류를 사는 고객층과 시간대가 맞는가 |
| 유동·접근 | 유동·접근성, 집객시설, 지하철 유동, 버스 유동 | 사람이 실제로 오가는가 |
| 경쟁·안정 | 경쟁 강도, 상권 안정성 | 경쟁이 덜하고 폐업이 적은가 |
| 주변 상권·관심 | 동반 카페, 동반 쇼핑, 검색 관심도, 카페 상권 지표 | 함께 방문하는 업종과 관심이 늘고 있는가 |

- 묶음 슬라이더 값은 그 묶음에 속한 그룹에 똑같이 나눠 적용한다. 고급 설정에서 개별 조정 시 묶음 표시는 "사용자 지정"으로 바뀐다.

#### 7-3. 동작 규칙
- **검증 기준**(v5 블렌드) 순위와 **내 조합**(사용자 비중) 순위는 배지와 색으로 구분한다. 내 조합에는 "검증 전" 표시를 붙인다. (v2)
- 내 조합이 13개 분기에서 기준보다 Top 10 평균이 높아도, 승이 패보다 많지 않으면 "우연일 수 있음" 안내를 표시한다. (v2)
- 근거 문장은 그룹 점수가 아니라 실제 값으로 쓴다. 예: "작년 같은 분기보다 매출 12% 증가", "반경 500m 지하철 승하차 상위 20%". (v2)
- 임대료·권리금은 포함하지 않으며, 상세 화면에서 외부 확인이 필요함을 안내한다. (v2)

- 구현: 단일 HTML(데이터 내장), 외부 서버 없음, GitHub Pages 배포.

### FR-08 후보 비교 (v2 신규)
- 목록에서 최대 3곳을 담아 나란히 비교: 등급, 매출 증가율, 묶음별 점수, 현재 점포 수, 유동.

### FR-09 내보내기 (v2 신규)
- 현재 필터·순위 기준의 후보 목록을 CSV로 내려받는다. 파일 첫 줄에 예측 분기, 순위 방식(검증 기준/내 조합), 생성 일시를 기록한다.

### FR-10 발표 자료
- 데이터 수집 정리 HTML(교수용), 전체 설명 PPT(기업 발표용, 격식체).

## 6. 비기능 요구사항
- 화면 첫 로딩 3초 이내(데이터 내장 파일 5MB 이하).
- 슬라이더 조정 후 13분기 재계산 0.3초 이내.
- 모바일 폭(375px)에서 목록·상세 확인 가능.
- API 키·개인정보 미포함. 저장소 업로드 전 키 검사.
- 디자인: 토스 디자인 문법 (Pretendard, 굵기·자간 위계, 흑백 + 파랑 포인트, 여백 중심).

## 7. 성공 기준
- 실무자가 설명 없이 3분 안에 자기 조건(자치구·규모)으로 "현장 조사 후보 5곳"을 고를 수 있다.
- 후보 목록을 CSV로 내려받아 그대로 내부 보고에 쓸 수 있다. (v2)
- 요인 비중을 바꿨을 때 과거 성적이 어떻게 변하는지 한 화면에서 확인된다.
- 화면의 모든 수치가 백테스트 결과 파일과 일치한다.
